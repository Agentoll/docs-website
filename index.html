import { agentTollFetch } from 'agent-toll';

const toll = agentTollFetch({
  wallet: '0xYourWalletAddress'
});

export async function middleware(request) {
  const response = await toll(request);
  if (response) return response;
  return NextResponse.next();
}

Configuration

Options

All options are optional. The only one you'll usually set is wallet.

Option Default Description
wallet none Your Base wallet address. Omit → operator receives 100% of payments.
receiptTtlSeconds 300 How long a paid receipt stays valid (seconds). Agents don't re-pay within this window.
paymentRpcUrl mainnet.base.org Base RPC URL for verifying on-chain payments. Use a dedicated provider for high-traffic production.
maxRequestsPerMinute none Rate limit per agent wallet per minute. Unset by default — no rate limiting.
maxSpendPerScope none USDC spend cap per agent per route. e.g. '1.0'
maxSpendTotal none Total USDC spend cap per agent across all routes.
metrics true Enable Prometheus-style metrics at /metrics. Enabled by default.
receiptStorePath .agent-toll-receipts.json Path to persist receipts to disk (Node.js only). Receipts survive restarts. Use a custom store for distributed deployments.
store FileStore Custom store object for Redis/KV/etc. Useful for horizontal scaling.
receiptSigningUrl none URL of a remote signing platform. Required for serverless/multi-replica deployments where a stable local key is unavailable. Must be paired with receiptSigningToken.
receiptSigningToken none Shared secret to authenticate with the remote signing platform.
receiptSignerPrivateKey auto-generated Explicit private key for signing receipts locally. Omit to auto-generate and persist to receiptStorePath.
Full example
agentToll({
  wallet: '0xYourWallet',
  receiptTtlSeconds: 300,
  maxRequestsPerMinute: 60,
  maxSpendPerScope: '1.0',
  maxSpendTotal: '10.0',
  metrics: true,
})
About

What Agentoll is

Agentoll is server-side middleware you add in front of your existing routes. It classifies each request: real browser traffic continues as usual; automated agents and crawlers hit a 402 Payment Required challenge with payment instructions, settle per that challenge, then retry with proof. The middleware verifies payment and issues a short-lived signed receipt so they are not charged again for every request.

Why it exists

AI systems and bots can pull your content or APIs at scale without your consent or compensation. Agentoll is a practical gate: you keep your app structure, add one integration layer, and only automated clients that complete payment get through protected paths.

What you add

Install the npm package and wire agentToll() (Express-style) or agentTollFetch() (Fetch runtimes like Next.js middleware). You optionally set a wallet address (0x…) to receive payouts. You do not build your own payment verification — that and receipts are handled by the middleware.

Defaults (at a glance)

Typical challenge amount is a tiny USDC sum per receipt; receipts default to about five minutes of reuse. With a publisher wallet configured, revenue is split between you and the platform operator; without a wallet, proceeds go to the operator (useful for testing).

Scope it deliberately. Toll applied globally can block search crawlers (for example Googlebot). Apply middleware only to routes you want to monetize or protect. Agentoll is in private beta — fit for pilots and early traffic, not a guarantee of production SLA.
